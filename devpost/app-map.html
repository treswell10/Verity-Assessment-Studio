Verity Assessment Studio — App Map

Verity is a proof of concept for AI-assisted marking that keeps a human teacher in charge of the final mark. A teacher uploads a marking memorandum, Verity (via Ollama) extracts the expected questions and answers, the teacher checks/corrects them, uploads one learner's script, and Verity proposes a mark per question with a reason and a confidence score — escalating low-confidence questions for mandatory teacher review before anything is signed off as final.

One action, traced: "Start AI Marking"

This is the kernel of the whole app — the moment the AI proposes marks and the teacher starts reviewing them.

1. Entry point

frontend/src/screens/ScriptReady.tsx — the "Start AI Marking" button calls an async onStartMarking prop and shows a disabled state + "Marking in progress…" while it awaits (marking three Ollama calls can take 60–120 seconds). Wired in frontend/src/App.tsx, which calls startMarking(script.id) from frontend/src/api/client.ts.

2. The logic

backend/app/routers/marking.py → start_marking(). Loops over every memorandum question, calls mark_answer() in backend/app/services/ollama_client.py (a structured-output Ollama call returning proposed_mark, reason, confidence), and saves one MarkingResult row per question with status="proposed".

3. The result

frontend/src/screens/MarkingScreen.tsx renders each result one at a time. If confidence is below CONFIDENCE_THRESHOLD (70, set in backend/app/config.py and mirrored in client.ts), the question is styled amber with "⚠️ Teacher Review Needed" and blocks advancing until "Confirm AI Mark" or "Change Mark" is used (ChangeMarkModal.tsx, PATCH /api/scripts/{id}/results/{question}).

To change this, start here

Adjust how strict escalation is → CONFIDENCE_THRESHOLD in backend/app/config.py (and the duplicate in frontend/src/api/client.ts — keep them in sync).
Change the marking prompt/reasoning style → mark_answer() in backend/app/services/ollama_client.py.
Change what happens after sign-off → sign_off() in backend/app/routers/marking.py and frontend/src/screens/MarkFinalised.tsx.

A practice to reuse

During the build, a report of "I click Start AI Marking and nothing happens" had two plausible causes: a backend failure, or a frontend UX gap. Checking the actual uvicorn request log showed no POST /api/scripts/{id}/mark request had arrived at all — which ruled out a backend crash and pointed straight at the frontend missing a loading indicator for a genuinely slow (60–120s) call. The reusable habit: when something "does nothing," check the actual request/log evidence before guessing which side of the system to change — it narrows the search immediately instead of debugging blind.

To run the app again: start the backend (uvicorn app.main:app --port 8000 from backend/, with MARKER_OLLAMA_BASE_URL/MARKER_OLLAMA_MODEL set) and the frontend (npm run dev from frontend/). This map reflects commit 51b3645 and is a snapshot — it can drift as the code changes.
