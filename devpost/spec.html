Structured Ollama Call (example)

POST http://localhost:11434/api/chat
{
  "model": "qwen2.5:7b-instruct",
  "messages": [...],
  "format": { "type": "object", "properties": { "question": {...}, "proposed_mark": {...}, ... } },
  "stream": false
}

→ { "question": "1.2", "proposed_mark": 2, "max_mark": 3,
    "reason": "Correct method, but the final answer is incorrect.",
    "confidence": 92 }

If parsing fails validation on the backend, that question is auto-flagged "Teacher Review Needed" instead of breaking the screen.

Important Failure Modes

No readable text extracted → "We couldn't read this file. Please try another file."
Ollama unreachable or returns invalid JSON → question auto-escalated, confidence 0, reason explains the parse failure.
Sign-off attempted with unresolved questions → 409, frontend shows which question(s) still need review.

What Was Simplified and Why

.txt / text-based .pdf only, no OCR or scanned images — matches the text-only model and scope's deferred handwriting OCR.
Self-reported model confidence instead of a calibrated score — simple, and sufficient to drive escalation.
All marking computed in one backend call, frontend steps through results — no websockets or background jobs needed.
No auth, single SQLite file — single teacher, single sitting, matches deferred multi-user scope.
